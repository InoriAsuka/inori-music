# v5.27.0 — UI 与播放解耦：`PlaybackEngine` 接缝

用户要求"把这套解耦合做了，让 UI 和播放分离"。

## 改造前的耦合

- `main.dart` 顶层有个 `late final InoriAudioHandler audioHandler` 全局。
- **四个不相干的 notifier** 用 `import 'package:inori_music/main.dart' show audioHandler` 反向抓它：`crossfade_notifier`、`speed_notifier`、`sleep_timer_notifier`、`eq_notifier`。这意味着它们每一个都传递依赖 `just_audio`，且不启动真实音频栈就无法测试。
- `InoriAudioHandler` 同时是四种东西：OS 媒体会话桥、`AudioPlayer` 持有者、gapless 队列、淡入淡出音量包络、Android 均衡器。
- `PlayerNotifier` 直接持有 `AudioPlayer` 并调用 17 个 just_audio 成员。
- UI 用 `Platform.isAndroid` 猜"有没有均衡器"——平台只是"当前引擎是否接了 EQ 效果"的代理，换引擎就是错的。

## 改造后

```
UI / notifiers  →  PlaybackEngine（抽象）  →  JustAudioEngine
                                          →  （将来）MediaKitEngine / Rust
                →  InoriAudioHandler（只剩 OS 媒体会话桥）
```

- **`lib/src/playback/playback_engine.dart`**：传输/队列/参数/观测/自省五组，外加 `EngineRepeatMode`、`EnginePlaybackState`、`EngineEqualizer`。
- **`PlaybackCapabilities`**：`equalizer` / `speedControl` / `gapless` / `crossfade` / `outputDeviceSelection` / `exclusiveOutput` / `outputFormatControl`。这是清单反复强调的那条规则的落点——**引擎做不到的控件就不该显示**。`JustAudioEngine` 诚实地把输出链三项报 false。
- **`lib/src/playback/just_audio_engine.dart`**：唯一 import `just_audio` 的文件。把播放器、gapless 队列、淡入淡出包络、Android EQ 全收进来——它们操作的是同一个播放器，分散在两个类里正是 `setVolume` 与淡入淡出互相打架的原因（旧代码靠 handler 上一个共享可变字段 `targetVolume` 勉强同步）。
- **`playbackEngineProvider` / `mediaSessionProvider`**：`main()` 里 override 注入，不再有全局。故意不提供默认实现——缺 override 是接线 bug，应该在启动时大声失败，而不是悄悄再起一个没人听的播放器。
- **`EngineEqualizer`**：band 数是**查询**不是常量。UI 固定十段、设备通常五段，写死就是把增益映射到错误的频率上。
- **`InoriAudioHandler` 瘦身到 120 行**，只剩 OS 控制进 / 播放状态出。

## 顺带修掉的两处

1. `_buildConcatQueue` 原本是"设置队列 → seek 到目标 index"，而 `if (concatIndex > 0)` 意味着**目标恰好是第一个有效 URL 时 seek 被跳过**。改为直接 `setQueue(urls, initialIndex:)` 一步到位。
2. `PlayerNotifier` 原本订阅 `processingStateStream` 和 `playerStateStream` 两条流；引擎把 just_audio 的 `processingState × playing` 矩阵收敛成五个状态，一条流够了。

## 验证

- `flutter analyze --no-fatal-infos`：0 error/warning（1 条 info 属存量文件）。
- `flutter test`：244/244 通过（235 存量 + 9 新增，含 2 例重写）。
  - **`test/playback_boundary_test.dart`（架构测试）**：`just_audio` 只能被引擎实现文件 import；任何文件都不得 `import main.dart`。接缝的价值全在于它守得住，这两条守不住的那天，换引擎就不再是受控改动。
  - `test/audio_notifier_engine_test.dart`：速度/淡入淡出真的送到引擎，且都在送达前钳位。
  - `test/eq_notifier_test.dart`：**新增"引擎有均衡器"整组**——这条路径以前只能在真实 Android 设备上跑，本地测试实际断言的是"测试机不是 Android"。现在覆盖了开启推增益、关闭全部归零、增益按设备范围钳位（用 5 段设备对 10 段 UI，逼出映射逻辑而不是 1:1 传递）。
  - `test/support/fake_playback_engine.dart`：可复用的测试假引擎。
