# Phase v5.12.3 — 本地曲目播放沙盒访问修复

**版本**: v5.12.3
**状态**: done（代码 + 静态验证完成；实际播放效果待远端 CI 构建后用户确认）
**方向**: Flutter 客户端

## 背景

用户下载 v5.12.2 构建实机导入一首真实歌曲后反馈：元数据（标题/艺术家）与封面正确显示，但曲目实际不播放，进度条与总时长停在 0:00。

推断根因：v5.12.0 让 `LocalLibraryTrack.localPath` 直接引用 `file_picker` 返回的原始选中路径。macOS App Sandbox 下 `NSOpenPanel` 授予的临时读权限不保证在选择动作之后持续有效——导入时同步读标签能成功（发生在选择的同一时间窗口内），但用户后续点击播放是独立交互，`just_audio`/`AVPlayer` 用同一路径重新打开文件时沙盒授权可能已失效，静默加载失败。

## 目标

本地导入的曲目复制到 App 自己的存储后播放，不再依赖对原始外部路径的持续访问。

## 任务清单

- [x] `local_library_notifier.dart`：`_importOne` 读完标签后把文件复制进新增的 `local_library_audio/` 目录（与既有 `local_library_covers/` 同级），`LocalLibraryTrack.localPath` 存复制后路径
- [x] `remove()`：同步清理复制出的音频文件（此前只清封面，遗留音频文件永久占用磁盘）

## 非目标

- 不改动 `player_notifier.dart`/`resolvePlaybackUrl` 等播放链路——问题出在数据源头（存了不可靠的路径），不在消费端

## 验证记录

`flutter analyze --no-fatal-infos` 0 issues；`flutter test --no-pub` 113/113 通过。本地无 Xcode 无法直接复现"导入后播放"链路，修复基于 macOS App Sandbox 已知行为模式推导，待远端 CI 构建后用户实机确认播放是否恢复正常。
