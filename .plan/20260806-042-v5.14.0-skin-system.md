# Phase v5.14.0 — 皮肤系统（切换 + 导入）

**版本**: v5.14.0
**状态**: done（代码 + 静态验证完成；视觉效果待远端 CI 构建后用户确认）
**方向**: Flutter 客户端

## 背景

用户三项 Flutter 客户端深度改造诉求的第三项之一（第一项 v5.12.0 游客本地播放、第二项 v5.13.0 启动页/登录页已完成）。改造前主题是 `sakura_dusk.dart` 里 `buildSakuraDuskTheme()` 硬编码的单一配色，`main.dart` 直接调用，没有任何抽象层，也没有第二套配色（`themeMode` 硬编码 `ThemeMode.light`）。

## 目标

主题抽象重构为可切换的 `SkinDefinition`；新增内置深色 ACG 皮肤；Settings 提供皮肤选择器；支持导入他人制作的 JSON 皮肤清单（含 WCAG 对比度校验，不达标仅警告不阻断）。

## 任务清单

- [x] 新增 `skin_definition.dart`：`SkinColors`（18 色 token，字段名与 `SakuraDuskColors` 一致）+ `SkinDefinition`（元数据）+ `buildThemeFromSkin()`（`buildSakuraDuskTheme()` 的泛化版本）
- [x] 新增内置深色皮肤「月靛」（Moonlit Indigo），全部核心文字/背景配对用新增的 `contrastRatio()` 实测 WCAG 4.5:1（`onSurface/surface` 13.9:1 等），品牌樱粉三色与默认皮肤保持一致
- [x] **范围扩大（相对最初规划）**：发现全仓库 ~250 处硬编码 `SakuraDuskColors.*` 引用后，把"存量调用点不强制本 phase 内迁移"改为全量迁移——不迁移会导致切换深色皮肤后大量文字不可读（近黑文字压在新的深色背景上），是功能缺陷而非可接受的不完整。新增 `SkinScope`（`InheritedWidget`）+ `context.skinColors` 扩展，24 个文件的调用点迁移完成
- [x] Settings → Appearance 新增「皮肤」入口：色块预览 + 即时切换 + 非内置皮肤可删除 + 导入按钮
- [x] 皮肤导入：`parseSkinJson()`，JSON 清单格式，结构性错误阻断导入并弹窗说明，WCAG 未达标仅警告
- [x] 新增 `skin_definition_test.dart`：25 例，覆盖 `contrastRatio`/`buildThemeFromSkin`/`parseSkinJson`（合法输入/结构性错误/对比度警告）/`SkinState.active`/`SkinScope.of`

## 非目标（相对最初规划的调整，理由见 requirement.md v5.14.0 条目）

- `SkinDefinition` 不含"可选背景图"字段——没有会消费它的调用点（启动页/登录页背景已由 v5.13.0 的独立 `backgroundProvider` 处理且刻意不随皮肤变化），加了就是死代码
- 启动页/登录页/品牌标识（`SplashScreen`/`LoginScreen`/`AppBackground`/`InoriMark`）刻意不接入皮肤系统，保持固定樱花薄暮配色——鉴权关卡之前的品牌入场体验与"应用内主题设置"在正常操作路径下不会同时出现在用户眼前
