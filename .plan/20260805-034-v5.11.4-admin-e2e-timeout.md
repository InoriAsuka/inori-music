# v5.11.4 — Admin E2E storage-tab 超时余量修复

日期：2026-08-05
状态：已完成

## 背景

v5.11.3 推送后监控远端 CI：`Web checks`/`Admin checks`/`Go API checks`/
`Flutter mobile checks`/`Web E2E` 五个 job 全部转绿——`Web E2E` 是此前
从未真正跑绿过的一个，验证了 v5.11.3 对 middleware/baseUrl 两个缺陷的
修复在真实 CI 环境同样生效。`Admin E2E` 从此前的 4/4 失败降到 1/4：
`storage tab renders storage backend list` 用例。

第一次尝试在 8000ms 内没等到 `<h1>Storage</h1>` 出现；重试时更早，在最
基础的 `getByLabel("Username")` 上就撞到了 `playwright.config.ts` 的
30000ms 整体测试超时。本地单独复测该用例耗时 15.3s，明显比同套件其余
三个用例（6.5s/7.9s/7.5s）慢。

这不是逻辑缺陷——`storage tab` 是四个用例里唯一从未真正执行到断言阶段
过的一个（此前 middleware/baseUrl 缺陷导致全部用例在登录阶段就失败）。
第一次真正跑到这一步，就暴露出 CI 共享 runner 资源下 Next dev server
编译 + 4 个顺序用例累积负载带来的余量比本地开发机紧得多。

## 实现

- `services/admin/playwright.config.ts`：整体测试超时 `30_000` → `45_000`。
- `services/admin/e2e/smoke.spec.ts`：`storage tab` 的 heading 断言超时
  `8_000` → `15_000`。
- 其余三个用例（login/users/catalog）本地耗时远低于各自超时，未改动。

## 验证

```bash
cd services/admin
npx tsc --noEmit                      # PASS
npx biome lint .                      # 39 files, 0 errors
E2E_USERNAME=ci_viewer E2E_PASSWORD=ci-password-123 npx playwright test
# 4 passed，storage tab 单次 15.3s（新超时 15s 断言 + 45s 整体仍有余量）
```

远端 CI 待本次推送最终确认。
