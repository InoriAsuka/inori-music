# Phase v5.15.1 — 桌面自定义标题栏在 macOS/Windows 上均未生效（修复）

**版本**: v5.15.1
**状态**: done（代码修复完成；本地无 Xcode/Windows 工具链无法编译验证，待远端 CI 编译 + 用户实机确认）
**方向**: Flutter 客户端

## 背景

用户下载 v5.15.0 构建实机验证，反馈 macOS 和 Windows 窗体外观"看起来跟以前一样"——自定义标题栏（`AppTitleBar`）没有生效。

## 根因（对照 `window_manager` 官方 example app 的原生 runner 文件逐行核实）

- **macOS**：`MainFlutterWindow.swift` 缺少 `override public func order(_:relativeTo:)` 覆写，AppKit 默认"启动时可见"行为抢在 Dart 侧 `waitUntilReadyToShow()` 应用 `titleBarStyle` 之前就把窗口显示出来。
- **Windows**：`flutter_window.cpp` 的 `OnCreate()` 里有一段从未改动过的 `flutter create` 脚手架代码（`SetNextFrameCallback` 触发 `this->Show()`），在首帧渲染完成瞬间无条件显示窗口，与 `waitUntilReadyToShow` 的顺序竞态。`window_manager` 自身的 `windowManager.show()` 已经会正确显示窗口，这段代码纯属多余。

## 任务清单

- [x] `macos/Runner/MainFlutterWindow.swift`：新增 `order(_:relativeTo:)` 覆写 + `hiddenWindowAtLaunch()`
- [x] `windows/runner/flutter_window.cpp`：删除 `OnCreate()` 里的 `SetNextFrameCallback`/`ForceRedraw` 冗余触发

## 验证记录

Dart 侧无改动，`flutter analyze`/`flutter test` 复核仍为 0 issues / 149/149。两处原生 runner 改动本地无法编译验证，依赖远端 CI 的 `Build macOS`/`Build Windows` job 真实编译兜底；实际标题栏是否生效待用户下载新构建后确认。
