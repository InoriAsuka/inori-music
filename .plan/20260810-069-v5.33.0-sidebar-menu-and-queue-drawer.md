# v5.33.0 — 侧栏菜单重做（EchoMusic 大平台骨架）+ 队列抽屉 + 三个实机反馈 bug

用户 v5.32.0 实机验收「基本满足要求」，转场与进度条通过。同时报了两个 bug、随后追加第三条：

1. 播放条时间标签换行（`0:43` 显示成两行 `0:4`/`3`）
2. 队列按钮打开的是播放页，不是播放队列

方向依据是 2026-08-10 定下的**统一设计语言**战略（`smooth-toasting-manatee.md`「批次三」）：不再追单一 OS 原生保真，改用 EchoMusic 那套自洽的跨平台语言；唯一例外是 macOS 红绿灯保持系统绘制。参照数据实测自 EchoMusic 源码（`github.com/hoowhoami/EchoMusic`，`src/renderer/layouts/Sidebar.vue`），已拉取核对而非凭印象。

## 第一部分：三个 bug

### Bug 1 — 时间标签换行

根因是**三个问题叠加**，缺一都不至于换行：

1. `_timeLabelWidth` 里的 `TextPainter` 没接环境 `MediaQuery.textScalerOf(context)`——渲染按系统放大后的字号，测量按 1.0。
2. `painter.width` 是小数，原样当作 `SizedBox.width` 等于**零余量**，段落布局一舍入最后一个字形就挤不下。
3. 那个 `Text` 没有 `maxLines: 1` / `softWrap: false` 兜底，于是它就换行了。

三条全部修正。测试在放大的 `textScaler` 下断言**实际渲染行数**仍为 1，而不是只断言 widget 存在。v5.32.0 那条「位数变化时轨道宽度不变」的断言保留未削弱。

### Bug 2 — 队列抽屉

这不是新 bug，是 v5.30.5 明确指示的临时做法（当时定为「没有从主界面打开队列的通路就先跳播放页，**不要为此新造队列 UI**」）。现在补正。

- 新增 `player/queue_drawer.dart` + `queue_drawer_provider.dart`：右侧滑出覆盖内容区，**不离开当前路由**，点外部或 Esc 关闭。
- 队列列表从 `full_player_screen.dart` 的私有 `_QueueList` 提取为公开的 `player/queue_list.dart`。**三个调用点共用一份**（全屏播放页侧栏面板 ×2、新抽屉）——两套实现一定会在重排/删除/跳播这些行为上分叉。

### Bug 3 — 播放条四边留白

此前是 `EdgeInsets.fromLTRB(8, 0, 8, 8)`：左右下三边都是 8，**唯独顶边是 0**，播放条顶边直接贴着上方内容区。

改为单个具名常量 `_outerMargin = 8.0` 经 `EdgeInsets.all` 应用。**关键是机制而不是数值**——四个独立字面量正是让其中三个达成一致、第四个掉队的原因；把那个 0 改成 8 只是掩盖，再补一个临时字面量会重复同一个错误。

测试直接量**封面到左边框与到上边框的距离是否相等**（容差 1px），不断言常量取值——否则改了常量测试照样过。

## 第二部分：侧栏菜单重做

范围：**只动桌面 `_DesktopSidebar`（≥1200dp）**。

### 账号卡片

原先是裸的一行，改成带浅填充的圆角卡片：头像 + 主行 + 次行 + 右侧齿轮进设置。游客态主行「未登录」、次行「点击登录账号」。`exitGuestMode()` 行为原样保留，只改外观。

### 可折叠分组

`发现音乐` / `我的乐库` 加折叠能力，状态经 `sidebar_group_collapse_provider.dart` 持久化——照 `coverFlowModeProvider` 的最小写法（SharedPreferences + Notifier），不造设置子系统。

### 分组内容：骨架立住，但不造死入口

用户拍板「摆出完整骨架，缺的做空状态」，实现时按规划阶段已说明的边界收了一处：

- **探索发现**（`discover/explore_screen.dart`）：用现有 catalog 接口做出**真内容**——最近添加 / 随机推荐两个区块。为此给 `CatalogRepository.listAlbums` 补了 `sortBy`/`sortOrder` 透传。`createdAt` 是服务端 `catalog/types.go` 里 `AlbumSortByCreatedAt` **已支持的真实取值**，核对过再加，不是推测出来的参数。
- **为您推荐**（`discover/for_you_screen.dart`）：引导性空状态，文案说明依赖后续版本。
- **私人 FM / 我的云盘刻意不做**：强依赖平台侧能力，本项目服务端完全没有对应物，摆出来就是点进去永远同一句话的死入口。

### 歌单分栏

`sidebar_playlists_section.dart`：`自建歌单`（`user_playlist_*` 本账户歌单）| `收藏歌单`（服务端策展 catalog playlists）两个 tab + 排序/刷新 + 「查看全部」入口。未登录时空状态引导登录。

### 底部两个入口

- **下载**：接既有离线下载能力（指向设置页 Offline Library），不新造下载系统。
- **装置**（输出设备选择）：读 `playbackCapabilitiesProvider.select((c) => c.outputDeviceSelection)`。当前 just_audio 引擎该位为 false，所以**现在完全不渲染**（不是渲染成禁用态）；等 media_kit / 自研引擎上报 true 时它自己出现。**是能力驱动，不是硬编码隐藏。**

## 回归守卫（重构中真的被打破过一条）

- **「移动端底栏仍是 6 个目的地」**——重构中间态一度打破，说明菜单重做漏进了移动端共享的扁平列表，已修正。`_TabletLayout` / `_MobileLayout` 最终保持原样。
- **「Playlists 可从侧栏到达」**——结构变了，断言改指新的歌单分栏路径，**没有因为重构被删掉**。行为断言不该随实现消失。
- **「渐变层不拦截点击」**（v5.31.0 的守卫）——保留，仅调整选择器。
- **`final index = flatIndex;` 闭包快照**——折叠分组让循环变复杂后仍保留。它是 v5.22.0「所有导航项都失效」那个 bug 的防线（闭包捕获循环变量本身，每个 tile 都上报最终索引）。
- **`Material(type: MaterialType.transparency)`**——v5.31.0 齐平化后侧栏靠它给 `ListTile` 提供 Material 祖先，重构中保持未丢。缺它选中态和 ink 会静默消失，本仓库踩过两次。
