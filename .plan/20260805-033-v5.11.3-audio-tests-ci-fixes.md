日期：2026-08-05
状态：已完成

## 背景

延续"继续小改动规划，暂不进入 v6"的既定方向，本阶段起点是收尾遗留任务
#74（P1 补全 Web 音频引擎关键模块测试：`crossfade.ts`、`audioGraph.ts`、
`trackGainCache.ts`、`playerStateSync.ts`）——v5.11.2 的"文档承诺测试补齐"
只覆盖了后两个模块，前两个仍缺测试。

写完测试后例行检查远端 CI 状态，发现 `Build` 工作流已经连续多次推送失败。
没有止步于"让最新一次推送变绿"，而是继续向前翻 CI 历史找第一次变红的
commit，结果发现失败一路可以追溯到 v5.5.0（2026-07-26）附近，中间跨越了
好几个互不相关的独立缺陷，其中两个是**真实产品缺陷**（不是环境或测试脚本
问题），已经在无人发现的情况下静默失败了 10 天到 44 天。

### 2. Build CI 缺陷排查（按发现顺序）

1. **Go gofmt 对齐失效**——`services/api/internal/userplaylist/types.go` 的
   `UserPlaylist` 结构体在 v5.11.0 新增 `SourceCatalogID`（更长字段名）后
   未重跑 gofmt。与 v5.5.1 同一类缺陷。`gofmt -w` 修复。
2. **Web `tsc --noEmit` 类型错误**——v5.11.2 提交前只跑了 `vitest run`（esbuild
   转译，不做完整类型检查），没跑 `tsc --noEmit`：
   - `trackGainCache.test.ts` 的 `makeApi()` 返回裸对象，6 处调用点与
     `resolveReplayGainDb` 期望的 openapi-fetch `Client` 类型不匹配。
   - `playerStateSync.test.ts` 的 `import type {...} from "./player-state"`
     路径本不存在（`LocalPlayerSnapshot` 在 `./playerStateSync`，
     `RemotePlayerState` 在 `@/lib/api/player-state`）；这个失败的导入把
     两个类型都替换成了 `any`，掩盖了后面 16 处真正的类型错误（`t()`
     构造的 `{id}` 不满足 `QueueTrack` 的完整字段）。
3. **Web：搜索历史下拉框 blur→refocus 后延迟自关闭**——
   `app/(app)/search/page.tsx` 的 `onBlur` 用 `setTimeout(150ms)` 延迟隐藏
   下拉，但从未在 `onFocus` 里清除这个定时器；150ms 内的 blur→refocus
   （`search-history.spec.ts` 的操作序列正是如此，真实用户快速交互时也会
   触发）会让下拉在用户仍聚焦的情况下被旧定时器凭空关闭。真实产品缺陷，
   不是测试时序假象。修复：timeout id 存 ref，`onFocus` 清除。
4. **Admin：`basePath` 与两处独立机制的错误交互**——
   - `middleware.ts` 的 `config.matcher: ["/admin/:path*"]` 在
     `basePath: "/admin"` 已配置的情况下会被 Next.js 自动再拼一次前缀，
     实际匹配式变成 `/admin/admin/:path*`，永远匹配不到真实请求，中间件
     形同虚设（未登录也能停留在受保护页面）。v4.8.0 把原本正确、不含
     `/admin` 前缀的 matcher 替换成了这个错误写法。同时修了配套的重定向
     目标二次前缀（`loginUrl.pathname = "/admin/login"` → `"/login"`），
     删除了基于错误前提写的 `stripBasePath()` 死代码。
   - `lib/api/client.ts`、`store/auth.ts` 的浏览器端 `baseUrl` 写死为
     `""`（从没有 basePath 的 web 端复制而来），导致浏览器发出的所有
     API 请求（含登录本身）都打到裸 `/api/v1/...`，未命中同样会被自动
     加 `/admin` 前缀的 rewrite 规则，落到 Next.js 自己的 404 页面；
     登录页把"无 data"一律显示成"Invalid credentials."，掩盖了请求根本
     没到达 Go API 的真相。此缺陷自 admin 拆分引入 basePath 的 v2.5.0
     起就存在（44 天），推测因"Bootstrap Token"登录通道不走这条路径而
     未被人工发现。两处改为 `baseUrl = "/admin"`。
   - 顺带修正 `smoke.spec.ts` 一处过期断言（表头实际文案是"User"不是
     "Username"），改为断言真实种子账号用户名出现在列表中。
5. **hygiene**：`services/admin/.gitignore` 补齐 `next-env.d.ts`、
   `test-results/`、`playwright-report/`，与 web 端对齐。
