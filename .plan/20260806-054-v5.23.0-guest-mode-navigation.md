# v5.23.0 — 游客模式导航重做（Spotube 对标）

分层交互架构重做第三阶段（对标 EchoMusic/Spotube/OriginalSound HQ 源码深度调研，见 `/Users/inorihimea/.claude/plans/smooth-toasting-manatee.md`）。

## 目标

- 游客模式从"单屏、无任何导航"升级成跟服务端模式同一套响应式导航壳，只是导航项精简。
- 本地曲库列表交互对齐 Spotube 的 `TrackTile` / 工具栏范式：播放全部/随机、库内搜索、hover 播放态、多选批量移除。

## 完成的改动

### 导航壳

- `lib/src/shared/widgets/shell_scaffold.dart`：`isGuest` 分支不再返回裸 `Scaffold`，改为走同一套 `_MobileLayout`/`_TabletLayout`/`_DesktopLayout`，只传入 `_guestItems`（本地曲库 + 设置）。
- `_NavGroup.header` 改为可空——游客模式只有两项，不值得再套一层分组标题。
- `_AccountBlock` 加游客分支：显示"游客"占位名，并**不**渲染设置图标（设置在游客模式下本身就是导航项，重复没有意义）。
- `_TabletLayout` 的 rail trailing 设置按钮同理，当设置已在 destinations 里时不渲染。
- `_MobileLayout` 的 `labelBehavior` 由导航项数量决定：>4 项用 `onlyShowSelected`（服务端模式 6 项），否则 `alwaysShow`（游客模式 2 项）。
- `lib/l10n/*`：新增 `localLibrary`、`guest` 文案（en/ja/zh）。

### 本地曲库

- `lib/src/local_library/local_library_screen.dart`：`ConsumerWidget` → `ConsumerStatefulWidget`（需要搜索词与选中集两份本地状态）。
  - 新增 `_Toolbar`：播放全部 / 随机播放 / 库内搜索框 / 曲目计数。此前该页**完全没有集合级播放入口**，也没有任何查找手段。
  - 库内搜索是纯客户端过滤（标题/艺术家/专辑，大小写不敏感）——本地曲库是单张小表，没有远端查询可打，也没有加防抖的必要。
  - 播放全部/随机/点行播放全部作用于**过滤后**的列表，否则筛完再点播放会静默忽略筛选条件。
  - 多选：长按进入选择模式（桌面端右键等价），选中态 app bar 显示计数 + 批量移除；选择模式下 leading 换成 `Checkbox`，行内单独的删除按钮隐藏（避免误触与语义重复）。
  - 选中集用 track id 而不是下标——并发导入/移除重排列表时下标会指向别的曲目。
  - hover：封面叠半透明播放/暂停图标（正在播放该曲时显示暂停），`MouseRegion` 对触摸输入天然不触发。
- `lib/src/local_library/local_library_notifier.dart`：新增 `removeAll(Iterable<String>)`，删完一批再重查一次，而不是每删一首重读整表；单首失败不中断整批（跟导入路径同一条规则）。`remove` 与它共用抽出来的 `_deleteOne`/`_refresh`。

## 与原计划的一处偏离（附理由）

原计划写的是"`LocalLibraryScreen` 改用 `DesktopSliverAppBar`"。实际实现保留了 `DesktopAppBar`：读 v5.21.0 自己写的 `DesktopSliverAppBar` 代码确认，它的拖拽区只包在 `FlexibleSpaceBar.background` 上（因为 `DragToMoveArea` 是盒模型 widget，不能包 Sliver），而本地曲库是列表页、不需要展开态大封面背景。传 `background: null` 迁过去等于**丢掉整条桌面拖拽区**——比现状更差。Spotube 的本地库页也是"固定工具栏 + 列表"，没有折叠 hero 头部。所以这里保持 `DesktopAppBar`（本来就有全宽拖拽），工具栏放在 body 顶部。
