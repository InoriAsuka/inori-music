# v5.26.1 — Windows 导入失败：非法文件名

v5.25.1 补上的导入错误上报第一次派上用场。用户在 Windows 上点导入，看到了确切报错：

> OSERR: 文件名，卷名语法不正确

这是 Windows 错误码 123（`ERROR_INVALID_NAME`）。

## 根因

`_importOne()` 直接拿 track id 当文件名：

```dart
final id = '$localTrackIdPrefix${const Uuid().v4()}';   // local:550e8400-...
await sourceFile.copy(p.join(audioDir.path, '$id${p.extension(path)}'));
//                    → ...\local_library_audio\local:550e8400-....m4a
final coverFile = File(p.join(coverDir.path, '$id.$ext'));   // 同样
```

`localTrackIdPrefix` 是 `'local:'`，而 **`:` 在 Windows 文件名里非法**（盘符与 NTFS 备用数据流的分隔符）。POSIX 只保留 `/` 和 NUL，所以 macOS 和 Linux 上一直正常，问题只在 Windows 显形——**游客模式在 Windows 上从来就没能导入过任何文件**。

## 修复

新增 `lib/src/shared/safe_file_name.dart`：`safeFileName(id)` 把 `< > : " / \ | ? *` 与控制字符替换成 `_`。

- **只清洗磁盘上的名字，id 本身保持 `local:` 前缀**——`PlayerNotifier` 靠它区分本地曲目与服务端曲目。
- DB 里存的是完整路径，所以旧构建写下的文件继续可用，不需要迁移。
- 顺带用在 `download_notifier.dart` 的离线文件名上：服务端 id 是裸 UUID，清洗后不变（不会孤立已有下载），但"拿 id 当文件名"正是刚炸过的模式，把约束在一个地方写清楚。

## 验证

- `flutter analyze --no-fatal-infos`：0 error/warning（1 条 info 属存量文件）。
- `flutter test`：235/235 通过（230 存量 + 5 新增）。
  - `test/safe_file_name_test.dart`：本地 id 去掉冒号、裸 UUID 原样不动（否则会孤立已有下载）、Windows 保留字符全替换、控制字符替换、普通标点保留（过度清洗会让文件名难以和 id 对应）。
- 待用户实机确认：Windows 上导入现在能成功。
