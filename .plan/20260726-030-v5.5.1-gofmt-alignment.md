# v5.5.1 — 修复 gofmt 对齐（Build CI 修复）

日期：2026-07-26
状态：已完成

## 背景

Build 工作流的 `gofmt -l services/api` 检查从 v4.8.4 起连续 7 个版本失败。
根因：v5.4.0 在 `services/api/internal/httpapi/handler.go` 的 `Handler` 结构体中
加了两个更长的字段名（`playerstateService`、`searchHistoryService`），但没有重跑
`gofmt`，导致结构体字段的对齐列宽整体失效。

本阶段只做纯格式化修复，零逻辑变更。

## 实现

- `gofmt -w services/api/internal/httpapi/handler.go` — 对齐列宽重排，字段名/类型/顺序
  完全不变
- 已验证 `git diff -w` 两侧归一化后完全一致（15 行加、15 行减，全部是空白调整）
- 本地 CI 等价检查全绿：format check PASS / vet PASS / go test 792 passed /
  go test -race 792 passed / OpenAPI JSON 校验 PASS

## 验证

```bash
test -z "$(gofmt -l services/api)"  # PASS
go vet ./services/api/...           # PASS
go test ./services/api/...          # 792 passed
go test -race ./services/api/...    # 792 passed
```

## 关联

- v5.5.0 的 Build 失败与前端主题改动无关
- 修复后 v5.6.0 及后续版本的 Build 工作流才能真实反映 Go 侧回归
