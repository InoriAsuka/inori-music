# v5.20.1 — 播放失败可见化（非确认修复，诊断可见性修复）

用户反馈 v5.20.0 实机验证后本地播放"还是无法播放"，即便 v5.16.0 已经修过一次确认的竞态 bug。开工前重新核实 v5.16.0 提交内容（`git show aaf751d`），发现此前会话总结中记录的"已加诊断日志 + 10 秒超时保护"从未真正提交——只有 await 修复本身落地。这次不是再猜一个新根因，而是先把静默失败变成可见失败。

## 根因分析

`playTrack()` 从 URL 解析到 `_audioPlayer.play()` 全程没有 try/catch。链路里任意一步抛出异常（最可疑：`just_audio` 原生层拒绝某个本地文件），在 `onTap: () => ref.read(...).playQueue(...)` 这类裸调用里就是一个未捕获的 Future 异常——release 构建下用户完全看不到，UI 侧此前没有任何反馈，表现正是"点击无响应"。

## 已排除的假设

`getApplicationSupportDirectory()` 在 macOS 上路径含空格（"Application Support"），怀疑 `'file://$path'` 朴素拼接产生未转义 URL。写脚本验证：`Uri.parse()` 生成 `.toString()` 时会自动对空格做 `%20` 编码，与 `Uri.file(path)` 结果完全一致——排除。

## 完成的改动

- `lib/src/player/player_state.dart`：新增 `PlaybackFailure`（故意不重写 `==`，保证同文本连续失败也能各自触发监听）+ `PlayerState.playbackError` + `copyWith` 的 `clearPlaybackError` 标志。
- `lib/src/player/player_notifier.dart`：`playTrack()` 整体包 try/catch，进入时清空旧错误，失败时写入 `playbackError` + `debugPrint` 完整堆栈；`resolvePlaybackUrl` 本地曲库分支补上 `File(local.localPath).existsSync()` 校验（`OfflineDb` 分支早就有，本地曲库分支之前没有）。
- `lib/src/shared/widgets/shell_scaffold.dart`：新增 `ref.listen(playerProvider.select((s) => s.playbackError))`，非空时弹 SnackBar——选这里因为它是游客/登录两种布局唯一共同的根 Scaffold。
- `test/player_notifier_test.dart`：新增 3 例。
