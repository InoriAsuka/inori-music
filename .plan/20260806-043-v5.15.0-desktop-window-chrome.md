# Phase v5.15.0 — 桌面自定义窗体

**版本**: v5.15.0
**状态**: done（代码 + 静态验证完成；实机走查待远端 CI 构建后用户确认）
**方向**: Flutter 客户端

## 背景

用户三项 Flutter 客户端深度改造诉求的第三项之二，也是这一轮三项诉求（游客模式 v5.12.0、启动页/登录页 v5.13.0、UI-UX 深度优化含皮肤系统 v5.14.0 + 桌面窗体 v5.15.0）的收尾。改造前桌面端（macOS/Windows）零自定义，完全用 `flutter create` 生成的默认原生窗体。用户已在计划阶段确认平台分工：Windows 完全自定义标题栏三按钮，macOS 沉浸式标题栏但保留系统红黄绿灯。

## 目标

隐藏原生标题栏；新增自定义标题栏组件，背景跟随当前皮肤；Windows 提供自绘的最小化/最大化/关闭按钮，macOS 保留原生红黄绿灯只做背景融入。

## 任务清单

- [x] `desktop_integration.dart` 的 `_initWindow()` 新增 `titleBarStyle: TitleBarStyle.hidden` + 按平台区分的 `windowButtonVisibility`
- [x] 新增 `AppTitleBar`（`lib/src/shared/widgets/app_title_bar.dart`）：背景色跟随 `skinProvider` 的 `playerBar` token；macOS 分支左侧留白给系统红黄绿灯 + 全宽可拖拽；Windows/Linux 分支用 `window_manager` 自带的 `WindowCaptionButton` 三按钮，`brightness` 跟随当前皮肤明暗
- [x] `WindowListener` 的 `onWindowMaximize`/`onWindowUnmaximize` 驱动最大化/还原图标切换，覆盖双击标题栏触发的状态变化
- [x] `main.dart` 的 `MaterialApp.router(builder:)` 单点接入，`DesktopIntegration.isDesktop` 门控，移动端不受影响；登录/启动页同样能拿到标题栏（否则隐藏原生标题栏后这些路由上用户无法移动/关闭窗口）
