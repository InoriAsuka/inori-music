# Phase v5.12.2 — 桌面窗体自适应尺寸

**版本**: v5.12.2
**状态**: done（代码 + 静态验证完成；实际观感待远端 CI 构建后用户确认）
**方向**: Flutter 客户端

## 背景

用户下载 v5.12.1 的 CI 构建实机验证游客本地播放模式后，提出窗口尺寸反馈：登录/启动页目前用的是主窗口的宽尺寸，应该固定成接近手机竖屏的"优雅比例"（参照截图 443×727）；进入本地曲库/主界面后再放宽（参照截图 2042×1191）。这是对已完成 UI 的窗体层面微调，不改动任何页面内部布局。

## 目标

登录/游客态未过闸时窗口固定为窄比例且不可调整大小；过闸进入主界面后放宽为可调整大小的宽窗口；两个方向的切换（登录↔主界面、包括登出）都要正确响应。

## 任务清单

- [x] 新增 `window_manager` 依赖（提前于 v5.15.0 引入，仅用其尺寸控制能力，标题栏自定义仍留给 v5.15.0）
- [x] `desktop_integration.dart`：`_initWindow()` 按冷启动时的 `authProvider` 值决定初始窗口尺寸/可调整性；新增 `applyWindowForAuthState(bool)` 供门禁状态翻转时调用
- [x] `main.dart`：`InoriMusicApp.build()` 内 `ref.listen(authProvider, ...)` 侦测 `isPastGate` 翻转并触发窗口尺寸切换

## 非目标

- 桌面自定义标题栏/去除原生窗体样式——仍属于 v5.15.0
- 皮肤联动的窗体配色——依赖 v5.14.0 才产出的皮肤 provider，本阶段窗体尺寸与皮肤无关

`flutter analyze --no-fatal-infos` 0 issues；`flutter test --no-pub` 113/113 通过。窗口尺寸切换的实际观感（初始尺寸有无闪烁、resize 动画是否顺滑）本地无 Xcode 无法验证，待远端 CI 构建后用户下载确认。
