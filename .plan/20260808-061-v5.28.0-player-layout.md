# v5.28.0 — 播放页布局：居中/分栏 + 控件分组

用户带截图的具体反馈：「播放界面看起来整体上方向对了，但是有些布局不太好」。三个点，外加一个参照。

## 修的三个问题

1. **关闭按钮压在 macOS 红绿灯上**（截图左上红框）。播放页是全屏路由、不走 `DesktopAppBar`，所以没有 `DesktopAppBar` 早就在做的红绿灯让位。新增 `_needsMacTrafficLightGutter()`，只在「桌面 + macOS + 未启用系统标题栏」时留 70px。
2. **控制条按钮排布不优雅**（截图下方红框）。原本是 `mainAxisAlignment: spaceEvenly` 撒开 8 个控件——播放/上一首/下一首和睡眠定时器获得完全相同的视觉权重，最常用的控件反而没法靠肌肉记忆找到。改成三组：次要控件贴两端，传输三件套在中间抱紧，且无论两侧各有几个次要控件都保持居中。
3. **封面下方那个小圆点**（截图红箭头）。那是 `PageView` 的页码指示器。宽屏现在歌词进侧栏，没有可翻的页，所以 `PageView` 和指示器一起只在窄屏保留。

## 新的居中/分栏（对标 Apple Music）

用户给的模型：不显示歌词和播放列表就居中，展开就左右分栏。

- 顶栏保持通栏，其下 `Expanded(Row([Expanded(播放器列), 侧栏]))`。
- **播放器列本身没有改动**，它只是拿到多少宽度就在多少宽度里居中——所以同一列同时服务两种状态，不会出现两套布局各自漂移。
- 侧栏 380px，内容是歌词或播放队列，用 `GlassPanel` 保持毛玻璃，让封面色场在整窗连续（不透明面板会把 v5.26.0 的背景切成两半）。
- 顶栏的队列/歌词按钮变成开关，**再按一次就关**，所以面板不需要自己的关闭入口也能退出（仍然给了一个 ×）。
- **只有宽窗分栏**（≥900px）。窄窗分栏会让两边都不可用，所以那里歌词仍是压入路由、队列仍是底部 sheet，跟改造前一致。
- 队列列表提取为 `_QueueList`，sheet 和侧栏共用，避免两处实现漂移。

## 实现中发现并修复的两个真问题（新写的单测抓的）

1. **`GlassPanel` 用 `DecoratedBox` 带背景色，里面的 `ListTile` 墨水和高亮被吃掉** —— 和 v5.22.0 侧栏那次是同一个缺陷（`ListTile` 画在最近的 `Material` 祖先上）。面板里全是列表行，所以这次立刻显形。改用 `Material` + `shape`。
2. **窄屏控制条溢出 78px** —— 8 个控件在手机宽度下放不下。查下来**改造前用 spaceEvenly 时同样会溢出**，只是没人测过。解法不是重排成两行（那样要维护两套排布），而是 `_ControlDensity`：窄屏时通过 `IconButtonTheme`/`TextButtonTheme` 压缩每个按钮的占位，**分组结构在任何宽度下逐字节相同**。

## 验证

- `flutter analyze --no-fatal-infos`：0 error/warning（1 条 info 属存量文件）。
- `flutter test`：251/251 通过（244 存量 + 7 新增）。
  - `test/full_player_layout_test.dart`：传输三件套确实抱紧且居中（跨度小于整条的一半，且中心与整条中心相差 <24px）、宽屏无 `PageView`、窄屏保留 `PageView`、队列按钮在宽屏停靠面板而不是盖住播放器、同一按钮再按关闭、开歌词会替换队列而不是叠加、**分栏后播放器在剩余宽度里居中**（断言 `(1400-380)/2`，而不只是"往左移了"）。
