# v5.26.0 — 封面驱动的配色（EchoMusic 流体背景 + 毛玻璃）

用户对 v5.21–v5.25 的实机反馈：「样式和色调都太丑了」，四个界面区域全部勾选。给出的方向很明确：

> 在封面的时候，可以参考 EchoMusic 那种渐变背景色……如果有封面，就从封面取色。在播放器页面就使用封面的颜色做动态变化并加入模糊的毛玻璃效果。EchoMusic 这种效果最符合 UI/UX 审美，**而不是深色冷色**。

并选择「先只改配色，看完再说」——所以本版本不动布局结构。

## 关键调研发现：EchoMusic 那个「渐变背景」不是渐变

读了 `src/renderer/views/lyric/LyricFluidBackground.vue`，实际做法是：

1. 把封面切成 4 个象限，各画进一个 **100×100** 的 canvas（`ctx.filter = 'blur(5px)'`）
2. 4 个 canvas 摆在中心 ±35%（以自身边长为单位）的位置
3. 每个 canvas 各自旋转（60s 一圈，延迟 -5s/-10s/-15s 错开）
4. 整个容器**反向**旋转（150s 一圈，scale 1.2）
5. `filter: saturate(1.3) brightness(1.5)` + SVG `feTurbulence`+`feDisplacementMap` 扭曲
6. 上面盖 `rgba(0,0,0,.24)` + `backdrop-filter: blur(64px)`

所以它是**封面自身的颜色分布在缓慢重组**，不是两个提取色之间插值。这也是为什么它永远和封面一致，而两点渐变永远只是近似。

## 完成的改动

### 新增 `CoverFluidBackground`（`lib/src/shared/widgets/cover_fluid_background.dart`）

上述技术的 Flutter 移植。象限用 `OverflowBox(alignment) + ClipRect` 实现——把 2 倍尺寸的图钉在某个角再裁掉，就等于取那一个象限，不需要解码成 `dart:ui.Image` 再手动 `drawImageRect`。饱和/亮度提升用一个 5×4 `ColorFilter.matrix`（saturate 1.3 × brightness 1.5 合并）。

**刻意没做**：`feTurbulence` 扭曲。Flutter 没有等价物，除非写 fragment shader；反向旋转 + 64px 模糊已经承担了主要效果。

### 新增 `artworkOverlaySkin`（`lib/src/shared/theme/artwork_overlay_skin.dart`）

播放器和歌词页原本是按「浅色皮肤上的深色墨水」写的，直接放到一个饱和的运动色场上会完全读不了。**没有去改那 ~30 处调用点**，而是派生一个皮肤，由屏幕用 `SkinScope` 包住内容——里面所有 `context.skinColors.x` 自动解析成覆盖层的值，调用点零改动。这正是 v5.14.0 那次 token 迁移换来的能力。

- 前景转白（不同透明度），表面转半透明白 → 卡片读作毛玻璃而不是遮住封面的实心块
- **强调色跟随封面**：`CoverPalette.accentOverArtwork`（vibrant → muted → dominant）替换品牌粉，进度条/播放键/选中态全部跟着当前封面走
- 取色未就绪时保持皮肤原强调色，不会闪过一帧无色状态
- `id` 里带上强调色，否则 `SkinScope.updateShouldNotify` 按 id 比较会导致切歌不传播

### 新增 `GlassPanel`（`lib/src/shared/widgets/glass_panel.dart`）

模糊 + 半透明填充 + 高光细边，三者缺一就塌成「半透明方块」。颜色走皮肤 token，所以在封面背景上自动拿到覆盖皮肤的半透明白，在普通页面上退化成普通表面卡片，调用点不需要分支。

### 接线

- `LyricsBackground` 重写：有封面 → `CoverFluidBackground` + `SkinScope(覆盖皮肤)`；无封面 → 纯皮肤色 `ColoredBox`，用户的真实皮肤原样保留。
- `FullPlayerScreen` **整页**放到这个背景上（此前只有 PageView 里的歌词 tab 有）。同时移除歌词 tab 内嵌的那层 `LyricsBackground`——否则会跑两套旋转贴片和两次 64px 模糊。
- 进度条 + 传输控制合并进同一个 `GlassPanel`，读作一整块浮在色场上的控制面，而不是散落的控件。

## 实现中发现并修复的一个真 bug（新写的单测抓的）

两个 `AnimationController` 是 `late final` **惰性初始化**，只有 build 的「有封面」分支会碰它们。无封面时它们从未创建，然后 `dispose()` 访问 `_tiles` 反而**在销毁过程中创建** Ticker → `Looking up a deactivated widget's ancestor is unsafe`。改为 `initState` 里显式创建，并按有无封面 `repeat()`/`stop()`——顺带解决了「没画背景却还占着 vsync 回调」。
