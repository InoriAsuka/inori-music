# Phase v5.16.0 — 修复已知问题：Windows sqflite FFI + 本地播放竞态

**版本**: v5.16.0
**状态**: done（代码修复完成，高置信度诊断；本地无法实机复现验证，待用户下载新构建确认）
**方向**: Flutter 客户端

## 背景

用户明确要求"后面一起修"的两个已知问题（v5.12.0/v5.13.0 实机验证时发现），排在 v5.15.0 之后处理：
1. Windows 登录/播放报 `databaseFactory not init`
2. macOS 本地导入曲目播放静音、进度条卡 0:00

## 根因与修复

- **Windows sqflite**：`pubspec.yaml` 从未接入 `sqflite_common_ffi`，Windows/Linux 桌面端任何 `OfflineDb`/`LocalLibraryDb` 访问都会抛异常。新增依赖 + `main.dart` 最前面按平台调用 `sqfliteFfiInit()` + `databaseFactory = databaseFactoryFfi`。
- **本地播放竞态**：`player_notifier.dart` 的 `playTrack()` 对带队列播放的场景，实际设置播放源委托给 `_buildConcatQueue()`，此前是**不被 await** 的 fire-and-forget Future，与紧随其后的 `await _audioPlayer.play()` 竞态——本地 SQLite 查询几乎没有真实等待时间，导致 `play()` 经常在播放源真正设置好之前就执行。修复为 `await _buildConcatQueue(...)`，同时把队列内逐首 URL 解析从顺序改为 `Future.wait` 并行，避免修复本身在长播放列表上引入启动延迟。
- 排除了「`ProgressiveAudioSource` 对 `file://` 处理不同于 `AudioSource.uri()`」这个候选假设——直接阅读 `just_audio` 源码确认 `AudioSource.uri()` 只按扩展名分支，与 scheme 无关，对本项目场景两种写法完全等价。
