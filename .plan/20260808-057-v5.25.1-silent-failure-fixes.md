# v5.25.1 — 歌词页入口与导入失败的两处静默失败

用户实机反馈触发的修复，两个问题是同一类：**功能失效时界面上什么都不显示**，跟 v5.20.1 之前播放失败的表现完全一样。

## 背景

用户以游客模式在 macOS 上播放了一个本地 m4a（轻音乐），反馈「歌词页按钮点了是没有反应的」；又在 Windows 上反馈「甚至连文件都没能导进来」。

## 问题一：歌词页按钮对无内嵌歌词的本地曲目被静默禁用

`full_player_screen.dart` 原本的门控：

```dart
onPressed: (trackId.isEmpty || (isLocalTrack && !hasLocalLyrics)) ? null : ...
```

本地曲目必须**带内嵌歌词标签**才允许打开歌词页。轻音乐/未打标的本地文件 `hasLocalLyrics == false` → `onPressed: null` → 按钮禁用、点了没反应、没有任何说明。

这个门控本身是多余的：`KaraokeScreen` 自己已经处理了空歌词（显示「No lyrics available.」），服务端曲目一直就是这么走的。

**影响远比"一个按钮"大**：歌词页是 v5.24.0（封面取色遮罩）和 v5.25.0（边缘渐隐、逐行虚化）**全部**视觉改动的唯一入口。游客模式 + 无歌词本地文件的用户，永远看不到这两个版本做的任何东西。

顺带修掉一个次生问题：`hasLocalLyrics` 用 `.valueOrNull ?? const []`，provider 加载期间为 null → 空列表 → 按钮短暂禁用，即使曲目其实有歌词。

**修复**：门控只保留 `trackId.isEmpty`，跟服务端曲目一致。

## 问题二：导入失败没有任何反馈

原本 `importFiles()`/`importFolder()` 返回 `Future<void>`，且：

- 按钮直接绑 `onPressed: notifier.importFiles` —— 抛异常就是未捕获异步错误，UI 上什么都没有
- `_importPaths` 的逐文件 `catch` 只 `debugPrint`

于是「选择器没打开」「元数据读失败」「文件复制失败」「写库失败」「用户取消」这五种情况，在界面上**完全无法区分**——都是点了没反应。Windows 上导入不进来正是撞在这里，而且这就是它一直没被发现的原因。

**修复**：新增 `ImportOutcome`（imported / failed / firstError / cancelled），三个导入入口全部改为经由 `_LocalLibraryScreenState._runImport` 上报：

| 情况 | 提示 |
|---|---|
| 整体失败 | 导入失败：<具体异常> |
| 部分失败 | 已导入 N 首，M 首失败（<首个异常>）|
| 全部成功 | 已导入 N 首 |
| 选了但没有可用文件 | 没有找到可导入的音频文件 |
| 用户取消 | 不提示（取消不是错误）|

空状态页的两个导入按钮改为由父组件传入回调（`_EmptyLocalLibrary` 从 `ConsumerWidget` 改为 `StatelessWidget`），因为**空曲库页正是失败最不可见的地方**——空的曲库保持空，看起来和取消一模一样。

## 未在本版本解决（需要决策）

**Windows 根本没有播放后端**。已核实 `just_audio` 0.9.46 只注册了 android/ios/macos/web，且 `just_audio_platform_interface` 的默认实现是 `MethodChannelJustAudio()`，没有任何平台兜底（对比 `audio_service` 在 Windows/Linux 上会退化成 `NoOpAudioService`，所以 App 能启动但一播放就抛 `MissingPluginException`）。这不是配置问题，是 Windows 版从来就没有播放能力。修它需要更换输出层（media_kit/libmpv），是独立的一批工作。
