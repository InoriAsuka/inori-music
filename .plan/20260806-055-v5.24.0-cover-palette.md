# v5.24.0 — 封面动态取色

分层交互架构重做第四阶段（对标 EchoMusic/Spotube/OriginalSound HQ 源码深度调研，见 `/Users/inorihimea/.claude/plans/smooth-toasting-manatee.md`）。与 v5.22/v5.23 相互独立。

## 目标

歌词页背景的渐变遮罩改用当前曲目封面提取的颜色，而不是固定皮肤色——这是 EchoMusic（强调色随封面变化）和 OriginalSound（歌词页取色渐变过渡）两份调研共同指向的点。

## 完成的改动

- `pubspec.yaml`：新增 `palette_generator: ^0.3.3+7`（Flutter 官方包，Material 动态取色用的同一套量化算法）。
- 新增 `lib/src/catalog/cover_palette_provider.dart`：
  - `CoverSource` 记录类型（`{albumId, localArtUri}`）作为 family key——记录自带结构化相等，不需要编码成字符串再解析回来。
  - `CoverPalette` 值类，只暴露 UI 真正要用的几个色板 + `backdropFor(Brightness)`。刻意不暴露 `PaletteGenerator` 本身：调用方不该需要知道它那七个可空色板里哪个合适，包类型不进 widget 代码，以后换取色实现也不会外溢。
  - `backdropFor` 的降级顺序对齐 Spotube `usePaletteColor`：muted → vibrant → dominant，按主题明暗取对应档。vibrant 永远不是首选——歌词背后放高饱和色会变成"上了色的洗底"而不是背景。
  - 取色前把图缩到 96×96 再量化：色彩分布不受影响，避免大封面第一次显示时卡住 raster 线程。
  - **所有失败路径都返回 null 而不是抛异常**：这是纯装饰，一张封面解码失败绝不能带垮显示它的页面。
- `lib/src/lyrics/lyrics_background.dart`：`StatelessWidget` → `ConsumerWidget`，渐变遮罩色改成 `palette?.backdropFor(skin.brightness) ?? context.skinColors.background`。两档不透明度（0.55/0.82）保持不变。遮罩包了 400ms `AnimatedContainer` 做切歌过渡。

## 范围内的取舍

- **不做取色驱动整个 App 强调色**：现有皮肤系统是"整体替换 18 个固定 token"的模型，让取色结果去动态替换 `ColorScheme.primary` 这类全局槽位会跟它正面冲突。这批只动歌词背景。
- **没做悬浮播放条进度条跟随取色**（计划里标注为"视时间成本决定，非必须项"）：`MiniPlayerBar` 常驻屏幕，在那里挂取色等于**每次切歌都在全 App 范围跑一次解码+量化**，代价跟一条 2px 强调线完全不成比例。取色的开销应该只由真正展示它的页面承担。
- **不做 K-Means++ LAB 空间取色**：`palette_generator` 内置算法够用，原计划已写明理由。
