# v5.29.0 — 播放页对齐 Apple Music 比例分栏 + 前景对比度修复

上一轮播放页重做（v5.26–v5.28）用户确认方向对了，但带截图给了三点新反馈和一个长期方向（完整规划见
`/Users/inorihimea/.claude/plans/smooth-toasting-manatee.md`）。本 phase 只做其中的
v5.29.0 一节：播放页对齐 Apple Music 的比例分栏，以及修复我在 v5.26.0 引入的前景对比度 bug。
主界面重做、Cover Flow、运行时插件 ABI、引擎更换留给 v5.30.0 及以后，本次不碰。

## A. 前景对比度修复（真 bug，优先）

`artworkOverlaySkin()` 此前注释写死"遮罩按构造一定是深色"，硬编码 `Brightness.dark` +
全白前景。这个假设不成立：背景实际是 `CoverFluidBackground` 对封面套
`saturate(1.3)×brightness(1.5)`（`_boost` 5×4 矩阵）之后叠 24% 黑
（`Colors.black.withValues(alpha:0.24)`），浅色封面提亮后依然是浅背景，白字白图标看不清——
用户截图里 "Botti, Chris" 和几个次要按钮几乎不可见。

- 新增 `backdropLuminance(CoverPalette)`：在 `Color` 的 0–1 归一化通道（`.r/.g/.b`）上原样
  复现 `_boost` 矩阵（矩阵没有平移列，线性变换在 0–1 空间和 0–255 空间等价），再
  `Color.alphaBlend(black 24%, boosted)`，取 `computeLuminance()`。
- `luminance >= 0.5` → 浅背景 → 前景转近黑（`Colors.black` 系列半透明值）；否则维持
  v5.26.0–v5.28.0 的白色处理不变（逐项验证过两者相等，这条分支零回归）。
- 冷背景（HSL 色相 180–280，青→蓝→紫）时把白前景向暖白（`0xFFFFF1E0`）微调 16%，只做这一点
  色相处理，不做完整互补色体系——范围里明确的取舍，避免把 v5.26.0 刚解决的"到处都是色"问题
  换个形式带回来。
- 播放/暂停按钮继续跟随封面强调色，不受明暗分支影响（用户明确说这一个跟主题色）。
- 派生皮肤的 `id` 把明暗档一起编进去（`#artwork-<accent>-<light|dark>`），否则
  `SkinScope.updateShouldNotify` 按 id 比较会漏掉"同一个强调色、但明暗翻转"的换肤。

## B/C. 播放器块与比例分栏

`full_player_screen.dart` 原来的结构是"控制面板 `Padding(horizontal:20)` 铺满区域宽"，
跟封面尺寸毫无比例关系；侧栏是固定 380px。改成：

- 新增两个顶层纯函数（可以不 pump widget 直接单测）：
  - `playerArtworkSize({regionWidth, regionHeight})` = `min(区域宽×0.42, 区域高×0.40)`，
    clamp 到 `[160, 420]`。比例量自四张不同尺寸的 Apple Music 参考截图。
  - `playerControlWidth({artworkSize, regionWidth})` = `(封面宽×1.45)`，clamp 到
    `[下限, max(下限, 区域宽-48)]`。1.45 是那四张截图量出的比值（1.38–1.52）的中点。
- 新增 `_playerBlock` 方法：封面 + 标题/艺术家 + 进度条 + 传输控制合成一体，标题和控制面板
  的外层 `Padding` 换成 `SizedBox(width: controlWidth)`，与封面共轴，在拿到的区域宽高里
  居中——未展开时区域是整窗，展开后是左半区，同一段代码服务两种状态。
- 侧栏从 `SizedBox(width:380)` 改成 `Expanded(flex:1)`，与播放器一侧对半分，外层套
  `Align(centerRight) + ConstrainedBox(maxWidth:560)`：窗口极宽时面板文字行不会无限变长，
  且被约束收窄后腾出的空间会回流给播放器一侧（直接把 `ConstrainedBox` 塞进 `Expanded`
  不会有这个回流效果——`Flex` 布局对 flex 子项的份额分配是一次性的，子项收窄不会触发
  兄弟节点重新分配）。
- 窄屏（< 900px，`canSplit=false`）保留写死的 280 封面——四张参照截图全部是桌面宽窗口，
  同一比例套到手机宽度上会明显更小，是可感知的倒退。

## 实现前已在设计阶段处理的两处坑

1. `(封面宽×1.45).clamp(下限, 区域宽-48)` 在区域宽很窄时下限会大于上限，直接 `.clamp()`
   抛 `RangeError`。用 `math.max(下限, 区域宽-48)` 做上限兜底，保证上限永远不小于下限。
2. `compactControls`（控制条是否收紧）此前用**整窗宽度** `MediaQuery` 判断。分栏后控制条
   实际只拿到半窗——1000px 窗口展开面板时整窗判断说"不用收紧"，但控制区域只有约 500px，
   会产生新的溢出，跟 v5.28.0 那次"窄屏 spaceEvenly 溢出 78px"是同一类判断基准错位，只是
   触发条件从"手机宽度"变成"中等宽度+展开面板"。改成按**控制条实际区域宽度**判断。

## 测试阶段又抓到一个规划完全没预料到的真问题

`_compactControlsBreakpoint` 原计划给的估算值是 480，要求跑测试校准。写了"中等宽度窗口
（950×700）展开队列面板，控制条不溢出"的测试后，**第一次跑是红的**：控制条实际宽度约
289px，溢出 40px。

关键发现：**溢出发生在控制条已经处于紧凑模式的情况下**（289 < 480，`compactControls` 早
已是 true）。这说明问题根本不在 480 这个阈值本身——480 后来证明完全不需要改——而在
`playerControlWidth` 的下限 280。这个数字是原计划的估算，从来没有验证过它是否真的能装下
紧凑模式的 8 个控件。

用临时诊断测试实测紧凑模式下的三段式布局（次要控件×2 贴左、传输三件套居中、次要控件×3
贴右）：

- 中间传输三件套固定 108px（3 × 36px，`skip_previous`/播放/`skip_next`）。
- 两侧各自用 `Expanded(flex:1)` 分剩余宽度的一半——这是让三件套无论两侧各有几个控件都
  保持居中的机制（v5.28.0 引入，有测试覆盖）。
- 右侧那组量出 116.4px（速度文本按钮 64.4px + 睡眠图标 26px + 收藏图标 26px），左侧那组
  只要 52px（重复 26px + 随机 26px）。等分机制下右侧只分到"剩余宽度的一半"，左侧多余的
  份额不会流给右侧——289px 控制条减去 `GlassPanel` 左右 28px 内边距、再减去中间 108px，
  剩余 153px 对半分，每侧只有 76.65px，右侧需要 116.4px，缺口 39.75px，正好对应实测的
  40px 溢出。

修复：把下限从 280 提到 400（新增具名常量 `_controlWidthFloor`，doc comment 里写清测量
依据），实测在最紧的场景下有约 15px 安全余量。**没有改动两侧 `Expanded` 等分这个居中机制
本身**——那是让传输三件套保持居中的关键设计，只有分栏后最窄的场景才会触到这个下限，为这
一种边界情况改掉核心居中机制不划算，收益和改动面不成比例。

补充验证了"宽屏不会被误判为紧凑"（480 阈值的另一半）：1400×1400 不分栏时
`controlWidth≈609`，按钮保持非紧凑尺寸（实测 48–52px）；1400×1000 分栏后
`controlWidth≈426`，落在 400–480 区间内，正确进入紧凑且不溢出。两个诊断测试文件用完即删，
没有留在仓库里。

## 测试

新文件 `test/artwork_overlay_skin_test.dart`（9 例，纯函数测试，不 pump widget，回避
`CoverFluidBackground`/`LyricsBackground` 的 `pumpAndSettle` 陷阱）：

- `backdropLuminance`：浅色 dominant ≥0.5，深色 dominant <0.5。
- 浅背景 → 前景近黑、`surface` 等于黑基底半透明值；深背景（暖色）→ 逐项等于 v5.26.0 以来
  的白色处理（回归保护）；`palette:null` → 保持深背景默认值不变。
- 强调色不随明暗分支翻转（同一个 `lightVibrant`、不同 `dominant` 的两个 palette，
  `sakuraPink` 相等）。
- 冷色暖化：深色+冷色调 → `onBackground != Colors.white` 且 `.b < .r`；深色+暖色调 →
  `onBackground == Colors.white`（只有冷色分支被微调）。
- id 编码明暗档：同强调色、不同明暗的两个派生皮肤，`id` 不同。

`test/full_player_layout_test.dart` 更新一条过期断言（`splitX` 期望值从写死的
`(1400-380)/2` 改成比例表达式 `1400/4`），新增 10 例：

- `playerArtworkSize`/`playerControlWidth` 纯函数的边界值（420 上限、160 下限、
  `RangeError` 兜底）与比值区间（1.4–1.5）。
- 宽屏封面撞 420 上限时控制面板宽度约等于 420×1.45。
- 窄屏仍是写死 280（PageView 的 `SizedBox`）。
- **中等宽度分栏不溢出**——这条最初真的跑红过，是它抓出上面 280 下限的问题。
- 宽屏不会被误判为紧凑（1400×1400 不分栏、1400×1000 分栏两个场景都验证过）。
- 超宽分栏时面板确实被 560 上限盖住。
